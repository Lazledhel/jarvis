# Jarvis

Отдельный голосовой ассистент для Android и собственного сервера. Версия исходников Android: 2.3. Не зависит от Liquid Home.

Имя «Джарвис / Jarvis» распознаётся локально через Vosk. Команда передаётся по HTTPS на сервер: Whisper распознаёт речь, AI/ML API формирует ответ и при необходимости выполняет поиск, Piper или XTTS синтезирует голос. Язык ответа определяется для каждой реплики. Контекст сохраняется три минуты после ответа; текстовые диалоги записываются только на сервере.

Телефон поддерживает подготовку звонка с подтверждением, маршруты в Google/Яндекс Картах и управление совместимым V2RayTun. Фоновое ожидание использует foreground service и микрофон; ограничения производителя и Android могут влиять на его работу при блокировке экрана.

## Сборка Android

Требуются JDK 17, Android SDK 35 и Gradle 8.9. Откройте корень проекта в Android Studio либо выполните `gradle :android:app:assembleDebug`. Путь к SDK задайте через `ANDROID_HOME` или локальный `local.properties` (он исключён из Git).

APK появится в `android/app/build/outputs/apk/debug/`. Используется отдельная локальная debug-подпись. Она не совпадает с подписью установленной личной сборки: не удаляйте рабочее приложение ради установки экспериментальной сборки. Личные ключи подписи и готовые APK не включены.

## Данные и зависимости

В репозитории нет личных адресов сервера, API-ключей, токенов, сертификатов, резервных копий телефона, контактов, журналов диалогов или пользовательской раскладки. Локальные конфигурации, модели, сборки и ключи исключены через `.gitignore`. Перед публикацией собственных изменений запускайте `python tools/check_public_tree.py`.

Лицензии сторонних библиотек и моделей определяются их авторами. Они не становятся частью прав на исходники этого проекта.

## 1. Подготовка Android

Выполните `python tools/prepare_assets.py`. Скрипт загрузит официальные английскую и русскую модели Vosk и сгенерирует короткий электронный сигнал. Все эти файлы остаются локальными и исключены из Git. После этого соберите APK.

Зависимости Android: Vosk Android 0.3.47 и JNA 5.18.1 из Maven Central. Аудиофайлы, голосовые образцы и модели из личной установленной версии не включены.

## 2. Сервер

Используйте отдельное виртуальное окружение Python 3.11: `python -m venv .venv`, затем установите `pip install -r server/requirements.txt`.

Скопируйте `server/.env.example` в `server/.env`. Впишите собственный `AIML_API_KEY` и сгенерированный случайный `PHONE_TOKEN` (например, через `python -c "import secrets; print(secrets.token_urlsafe(32))"`). Это разные секреты: API-ключ остаётся на сервере, на телефон передаётся только `PHONE_TOKEN`.

Положите собственные TLS-файлы `server/server.crt` и `server/server.key`. Сертификат должен соответствовать имени в `server_url`. Для внешнего доступа настройте интерфейс прослушивания через `JARVIS_BIND_HOST`, маршрутизацию и сетевые правила самостоятельно. В исходниках нет адреса конкретного сервера, а по умолчанию сервис доступен только на localhost.

Whisper по умолчанию использует medium на CUDA. Для CPU задайте `WHISPER_DEVICE=cpu` и `WHISPER_COMPUTE_TYPE=int8`. Модели автоматически загружаются в локальный каталог models. При необходимости задайте `WHISPER_MODEL_DIR`, `JARVIS_DIALOG_DIR` и `JARVIS_TIMEZONE`. На Windows путь к дополнительным DLL CUDA можно задать через `JARVIS_CUDA_DLL_DIRS`.

Для Piper разместите выбранные `.onnx` и `.onnx.json` в `server/voices/`. Русский идентификатор — `ru_RU-denis-medium`, английский задаётся `JARVIS_EN_VOICE` (по умолчанию `en_GB-jarvis-high`). Голоса необходимо получить отдельно с соблюдением их лицензий. Запуск: `python server/server.py`.

Для опционального XTTS требуется совместимое окружение с `server/requirements-xtts.txt`, CUDA, модель в `server/model/` и разрешённый голосовой образец `server/reference/jarvis-reference.wav`. Укажите `JARVIS_TTS_ENGINE=xtts`; сначала запустите `python server/voice_worker.py`, затем основной сервер. Голосовой процесс использует тот же `.env` и локальное имя localhost. Модели и образцы в репозитории отсутствуют; их лицензии действуют отдельно.

## 3. Привязка телефона

Создайте **локальный** файл `local/provision.json` по образцу `provision.example.json`: задайте внешний HTTPS URL и тот же `PHONE_TOKEN`, что на сервере. Адрес не имеет запасного локального варианта.

После установки и первого открытия приложения скопируйте этот файл в каталог приложения через ADB:

```sh
adb push local/provision.json /sdcard/Android/data/ru.local.jarvis/files/provision.json
adb push server/server.crt /sdcard/Android/data/ru.local.jarvis/files/server.crt
```

Полностью перезапустите приложение, чтобы импортировать привязку. Файл provision.json на телефоне удаляется после импорта; сертификат остаётся для проверки HTTPS. Авторизация и проверка имени сервера не отключаются.

При открытии интерфейс автоматически проверяет сервер; цветной индикатор рядом с названием показывает результат. Включите ожидание имени и разрешите микрофон. Разрешения телефона и контактов запрашиваются один раз при первом запуске, если ещё не выданы. Доступ поверх приложений нужен для открытия действий вне Activity.

## Проверки

Из каталога server: `python -m unittest test_dialogues test_provider test_reply_language test_speech_errors`. Эти тесты не требуют реального API-ключа и не обращаются к личному серверу; пакет openai должен быть установлен. Полный тест звука и работы на заблокированном экране выполняется отдельно на целевом устройстве.

## Исправление длинных голосовых ответов
XTTS с enable_text_splitting требует spaCy: зависимость включена в requirements-xtts.txt. Отсутствие библиотеки ломало длинные ответы, хотя короткие работали. Дополнительно сбои синтеза возвращают диагностическую ошибку 503 с кодом обращения; ограниченный журнал speech-errors.log содержит только тип исключения и номера строк, без текста запросов, токенов и адресов.

## Интерфейс 2.2
Убраны поясняющие тексты, статусы, расшифровка и кнопки ручной команды, выдачи разрешений и проверки связи. Сохранены ожидание, выключение, текстовый ввод и очистка контекста. Проверка /health выполняется асинхронно при открытии интерфейса; периодического опроса и UI-таймера нет. Индикатор: зелёный — готов, жёлтый — нет ключа провайдера, красный — ошибка; касание показывает подробность. Запрос контактов/звонков защищён флагом первого запуска и не повторяется после отказа. Ранее выданные разрешения сохраняются.

## Голосовой экран 2.3

Текстовый ввод, отправка текста, очистка контекста кнопкой и текстовый вывод отсутствуют. На экране остаются название, индикатор связи, реактор и включение/выключение ожидания. Нативный Canvas-реактор вдохновлён [референсом RabbitArts](https://rabbitarts.github.io/Jarvis_website/); CSS, WebView и графические файлы сайта не используются. Пульсация следует RMS-огибающей фактически воспроизводимого WAV, а во время записи — уровню команды. Анимация работает только при открытом интерфейсе; дополнительного захвата микрофона ради визуализации нет.

## Передача задач компьютеру

Скажите **«Джарвис, на компьютере …»** и сформулируйте задачу. Фраза «на компьютере» принимается в начале или конце текущей команды. Обычные вопросы остаются на телефоне: результаты поиска и ответы модели сами по себе режим не включают.

Сервер подготавливает до восьми шагов через настроенный AI/ML API и сохраняет задание в SQLite. Каждая команда становится отдельным чатом Codex. Результат остаётся в этом чате; телефон произносит подтверждение постановки в очередь, а не обещание завершённого действия.

Локальный worker подключается к серверу по исходящему HTTPS с проверкой сертификата. Входящий порт на ПК не нужен. Worker использует документированный [Codex App Server](https://learn.chatgpt.com/docs/app-server) и существующий локальный вход Codex. Локальный RPC работает через stdio и не публикуется в сеть.

### Настройка

1. Сгенерируйте новый отдельный случайный секрет для `COMPUTER_BRIDGE_TOKEN` в серверном `.env` либо укажите защищённый `COMPUTER_BRIDGE_TOKEN_FILE`. Не используйте `PHONE_TOKEN` или ключ AI/ML API для этой роли. Перезапустите сервер.
2. На компьютере установите/откройте Codex и войдите в аккаунт. Создайте частный `desktop/local/config.json` по образцу `desktop/config.example.json`. Укажите адрес своего сервера, новый секрет, публичный TLS-сертификат сервера, путь к codex.exe, отдельную папку задач и SQLite состояния. Лучше использовать абсолютные локальные пути.
3. Для ручного запуска: `python desktop/worker.py --config desktop/local/config.json`. Нужен Python 3.11+; сторонних Python-зависимостей у worker нет.
4. Для запуска при входе в Windows выполните `desktop/install.ps1`, передав абсолютный путь конфигурации и путь к pythonw.exe. Worker должен работать от того же пользователя Windows, который вошёл в Codex. Секреты и SQLite защитите правами этого пользователя.

Задачи создаются с `workspace-write` и `on-request` в отдельной подпапке. Дополнительные запросы доступа и другие серверные RPC-запросы worker автоматически не подтверждает: задача помечается как требующая внимания, продолжение выполняется в Codex. Подмена пути программы, параметров прав и рабочей папки заданием с сервера не поддерживается.

Состояние задач и аренды очереди сохраняются. Повторная доставка известного задания не запускает второй turn. Если процесс оборвался в момент создания чата до получения его ID, автоматического повторного запуска нет: нужна ручная проверка, чтобы не выполнить действие дважды. Итоговый текст и документы Codex обратно на сервер не выгружаются — передаются только ID и состояние.

Для остановки: остановите/удалите задачу планировщика `JarvisDesktopBridge` и отключите секрет моста на сервере. Очередь и чаты не удаляются. Образцы конфигурации содержат только заглушки; реальные секреты, модели, сертификаты и журналы не публикуются.

### Проверки моста

В каталоге server: `python -m unittest test_computer_bridge`. В каталоге desktop: `python -m unittest test_worker`. Проверяются явная голосовая активация, отдельный токен, аренда/восстановление очереди и отсутствие повторного запуска при повторной доставке.

### Видеопамять при простое

Whisper и XTTS загружаются только при распознавании и синтезе.
Через 60 секунд без использования каждая модель освобождается; следующая
команда загружает её заново. Таймер отсчитывается после завершения работы,
выгрузка защищена от одновременного выполнения запроса. Проверка связи
не загружает модели. Детектор имени на телефоне работает независимо.

Интервал задаётся переменной окружения `JARVIS_GPU_IDLE_SECONDS`
для обоих серверных процессов (по умолчанию 60). После холодного старта
ответ дольше; небольшая служебная память CUDA может сохраняться в процессе.
